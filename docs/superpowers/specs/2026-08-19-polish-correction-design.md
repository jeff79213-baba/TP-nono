# 設計文件：提升語音輸入的潤飾錯字修正能力

日期：2026-08-19

## 目標

語音辨識（STT）輸出的文字常含有明顯聽錯的字詞（例如「任世的攻擊」→ 應為「潤飾的功能」）。
目前潤飾 prompt 過度保守（「不確定的字就原樣保留」），導致錯字修正不足。

本次改動讓 LLM 在「不破壞句子結構與語氣」的前提下，依上下文積極改正明顯聽錯的字詞。

## 方案選擇

使用者選定方案 A：在現有 prompt 上放寬錯字修正規則，保留句子結構與語氣保護。

## 新版 prompt

```
你是一個語音辨識文字校正器。請依上下文把語音辨識的錯字修正確：

1. 刪除口語贅詞（僅限：嗯、啊、喔、那個、這個、就是說）
2. 依上下文改正明顯聽錯的字詞（如同音字、近音字、語意不通的字）
3. 繁體中文輸出

禁止事項（絕對遵守）：
- 禁止改寫句子結構或調整語序
- 禁止改變語氣（疑問句不准改成陳述句）
- 禁止添加、刪除原意以外的內容（贅詞除外）

只有無法從上下文判斷的字才原樣保留。只輸出校正後的文字，其他什麼都不要做。
```

### 與舊版差異

| 項目 | 舊版 | 新版 |
|------|------|------|
| 錯字修正 | 修正「明顯的語音錯字」 | 依上下文改正「明顯聽錯的字詞（同音/近音/語意不通）」 |
| 保留規則 | 不確定的字就原樣保留 | 只有無法從上下文判斷的字才原樣保留 |
| 結構/語氣保護 | 禁止改寫句子結構、改變語氣 | 相同（維持） |

## 修改範圍

1. `~/.voice-typer/config.toml` — 使用者的實際設定（`llm.system_prompt`）
2. `voice-typer/src/config/manager.py` — `LlmConfig.system_prompt` 預設值
3. `voice-typer/config.toml` — 範本預設值

## 驗證方式

1. 用測試腳本以真實設定呼叫 Groq LLM，輸入使用者提供的錯誤範例
   「現在有人自助來了只是任世的攻擊不太強」
   預期輸出接近「現在有文字出來了 只是潤飾的功能不太強」
2. 確認輸出不含 ` thinking` 區塊、非空字串
3. 重啟程式確認無錯誤
